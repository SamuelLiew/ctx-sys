# F1.1 Ignore File Defaults

**Phase**: v2 / Phase 1 — Focus & Sharpen
**Priority**: High
**Dependencies**: none

## Goal

`ctx-sys init` should generate a `.ctxignore` with sensible defaults, and indexing should stop reading `.gitignore` by default. Users opt in to `.gitignore` if they want it.

## Why

Today, [src/indexer/ignore-resolver.ts](../../src/indexer/ignore-resolver.ts) merges `DEFAULT_EXCLUDE + .gitignore + .ctxignore` with both `useGitignore` and `useCtxignore` defaulting to `true`. That's wrong for our use case:

- **`.gitignore` is for git, not for retrieval.** A file can be perfectly worth indexing yet untracked by git (generated API client code that lives in `dist/`, large committed fixtures excluded from a feature branch, the contents of `.env.example`). Conversely, plenty of files git tracks shouldn't be indexed (generated lockfiles, fixtures with PII, vendored libraries the user doesn't write).
- **Index quality depends on intentional curation.** `.gitignore` was written for a different question; reusing it silently surprises users when their indexed corpus contains noise or omits useful files.
- **Init currently writes no ignore file.** Users discover the `.ctxignore` knob only by reading source — `ctx-sys init` should make it visible.
- **A bare `.ctxignore` makes the boundary obvious.** Users see the file in their repo, edit it, commit it, and know exactly what shape the index has.

## Behavior change

### `ctx-sys init` writes `.ctxignore`

Generate `<project>/.ctxignore` with this seed content:

```gitignore
# .ctxignore — patterns excluded from ctx-sys indexing.
# Same syntax as .gitignore (one pattern per line, # for comments).
# Edit freely; this file is intended to be committed.

# Build output
dist/
build/
out/
.next/
target/
*.tsbuildinfo

# Dependencies (already covered by DEFAULT_EXCLUDE; listed for visibility)
node_modules/
vendor/
.venv/
venv/
__pycache__/

# ctx-sys & sibling tooling state
.ctx-sys/
.yaao/
.yaao/worktrees/
.lean-ctx/

# Lockfiles & large generated artifacts
package-lock.json
pnpm-lock.yaml
yarn.lock
Cargo.lock
*.min.js
*.map

# Test fixtures (uncomment if your fixtures are large or noisy)
# tests/**/fixtures/
# **/__snapshots__/

# Secrets — never index these
.env
.env.*
*.pem
*.key
```

- If `.ctxignore` already exists, `init` leaves it untouched and prints a note.
- `init --force` overwrites.
- A new flag `init --no-ignore-file` suppresses creation for users who manage it via their dotfiles or another tool.

### `useGitignore` default flips to `false`

In `IgnoreResolver` options:

```ts
export interface IgnoreResolverOptions {
  useGitignore?: boolean;   // default: false  (was true)
  useCtxignore?: boolean;   // default: true
  // ...
}
```

### New config knob

In `.ctx-sys/config.yaml`:

```yaml
indexing:
  use_gitignore: false       # default — set true to also respect .gitignore
  use_ctxignore: true        # default
  ignore:                    # additional inline patterns (unchanged)
    - some/extra/path
```

`use_gitignore: true` is the documented way to layer `.gitignore` on top of `.ctxignore`. Order of precedence (highest priority last): `DEFAULT_EXCLUDE` → `.gitignore` (if enabled) → `.ctxignore` → inline `ignore:` patterns.

### CLI overrides

- `ctx-sys index --use-gitignore` — one-shot enable for this run.
- `ctx-sys index --no-ctxignore` — one-shot disable (already exists in spirit; formalize).

## Migration

For existing projects (already initialized, no `.ctxignore`):

- First run of `ctx-sys index` on schema v2 prints a one-line notice:
  > `ctx-sys` no longer reads `.gitignore` by default. Run `ctx-sys init --no-config --ignore-only` to generate a `.ctxignore`, or set `indexing.use_gitignore: true` in `.ctx-sys/config.yaml` to restore the old behavior.
- The notice prints once, then a flag in the DB suppresses it.
- New `ctx-sys init --ignore-only` subcommand generates just the `.ctxignore` without touching `config.yaml`. (Or fold into `init` as an additive flag — implementer's call.)

## Edge cases

- **Monorepos.** Each subproject can have its own `.ctxignore`; resolution walks upward from the indexed file just like `.gitignore` does. Implementation already supports this via `parseGitignore` — port the same walker to `parseCtxignore` if it isn't already shared.
- **`.dockerignore` / `.npmignore`.** Out of scope. Users who care can copy patterns into `.ctxignore`.
- **Negation patterns (`!pattern`).** Already supported by the gitignore parser; document that `.ctxignore` shares that semantics.

## Acceptance criteria

- [ ] `ctx-sys init` creates `.ctxignore` with the seed content above (idempotent on re-run).
- [ ] `IgnoreResolver` defaults: `useGitignore = false`, `useCtxignore = true`.
- [ ] `indexing.use_gitignore` / `indexing.use_ctxignore` in project config are honored.
- [ ] `--use-gitignore` and `--no-ctxignore` flags exist on `ctx-sys index`.
- [ ] One-time migration notice prints for users upgrading without a `.ctxignore`.
- [ ] README "Configuration" section documents the change.
- [ ] Tests cover: (a) no `.gitignore` read by default, (b) opt-in still works, (c) seed `.ctxignore` is well-formed and parses without errors.
