# F1.6 Local Model UX

**Phase**: v2 / Phase 1 — Focus & Sharpen
**Priority**: High
**Dependencies**: F1.2 (default models referenced everywhere)

## Goal

Reduce the friction from `npm install -g ctx-sys` to working index to as close to zero as we can get. Three threads:

- **(A) Bootstrap script** — `ctx-sys setup` does everything: detects backend, installs Ollama if absent, pulls required models, sanity-checks.
- **(B) Multi-backend support** — Ollama is the default, but llama.cpp / llamafile / LM Studio / OpenAI-compatible endpoints all work through one provider abstraction.
- **(C) Preflight + diagnostic UX** — every local-model-touching command does a fast pre-check; every failure mode produces one actionable line; `ctx-sys doctor` consolidates diagnostics.

Together these turn "first 60 seconds" from "stack trace and google" into "ran one command, worked."

---

## A. `ctx-sys setup` — one-command bootstrap

### Behavior

```bash
ctx-sys setup
```

End-to-end interactive (or `--yes` for non-interactive) setup that handles every step a new user has to do today. Concrete flow:

1. **Backend detection.**
   - Detect Ollama on PATH and reachable at `http://localhost:11434`.
   - Detect llama-server (llama.cpp) on PATH.
   - Detect LM Studio's `lms` CLI.
   - Detect existing OpenAI key in env.
2. **Choose backend.** If multiple are present, prompt. If none, recommend Ollama and offer to install it (see below).
3. **Install Ollama if needed.**
   - macOS: `brew install ollama` if Homebrew is present; otherwise `curl -fsSL https://ollama.com/install.sh | sh` after explicit y/n confirmation showing the URL.
   - Linux: `curl -fsSL https://ollama.com/install.sh | sh` after explicit confirmation.
   - Windows: print direct download link; don't auto-install.
   - Never silently auto-execute install scripts — always show what's about to run.
4. **Start the backend** (Ollama or llama-server) if not running. For Ollama: `ollama serve` in the background; record PID; tell user how to stop it.
5. **Pull required models.**
   - Embedding: `ollama pull mxbai-embed-large:latest` (~1.5 GB).
   - Summarization + HyDE (optional, disabled by default per F1.2): `ollama pull gemma3:270m` (~300 MB).
   - Show progress bars from the backend; don't hide them.
6. **Write config.** Generate `.ctx-sys/config.yaml` reflecting the chosen backend and `.ctxignore` per F1.1.
7. **Sanity check.** Run `ctx-sys doctor`. Print PASS/FAIL per component. If anything fails, print the recovery step.
8. **Optional first index.** Offer to run `ctx-sys index` immediately.

### Flags

- `--yes` — non-interactive; accept all defaults; fail if a step needs human input.
- `--backend ollama|llama-cpp|lm-studio|openai` — skip detection prompt.
- `--no-models` — set up backend but skip model pulls (for users with bandwidth concerns).
- `--no-install` — never install anything; only configure existing tooling.

### What we won't do

- Bundle Ollama in the npm package (size, license, platform matrix).
- Auto-update Ollama or models.
- Silent network downloads. Every fetch is shown and confirmed.

## B. Multi-backend provider abstraction

### Why

Ollama is great but isn't the only local backend. Users have reasons to want alternatives:

- **llama.cpp** (`llama-server`) — lower overhead, more model formats, more control.
- **LM Studio** — popular GUI tool with an OpenAI-compatible server.
- **llamafile** — single-file portable inference.
- **OpenAI-compatible endpoints** (vLLM, TGI, LiteLLM, Ollama itself) — many local servers expose the OpenAI API shape.
- **Cloud OpenAI** — already supported as fallback; tighten the abstraction.

Today's `ctx-sys` has `providers.ollama` and `providers.openai` knobs but the code path likely has Ollama-specific assumptions. F1.6 cleans this up.

### Design — a tight provider interface

```ts
// src/embeddings/provider.ts
export interface EmbeddingProvider {
  name: string;                                  // "ollama" | "openai" | ...
  embed(texts: string[]): Promise<number[][]>;
  dimensions(): number | Promise<number>;        // auto-detect if unknown
  healthCheck(): Promise<ProviderHealth>;        // ok / model-missing / unreachable / ...
}

// src/summarization/provider.ts (parallel shape)
export interface CompletionProvider {
  name: string;
  complete(prompt: string, options?: { maxTokens?: number }): Promise<string>;
  healthCheck(): Promise<ProviderHealth>;
}

export interface ProviderHealth {
  status: 'ok' | 'unreachable' | 'model_missing' | 'auth_failed' | 'unknown';
  detail?: string;                               // human-readable explanation
  fix?: string;                                  // copy-pasteable recovery command
}
```

All retrieval, summarization, and HyDE call into the interface. Adding a new backend = one file implementing the interface + a registration line.

### Backends shipped at v2.0

| Backend | Embedding | Completion | Notes |
| --- | --- | --- | --- |
| `ollama` | ✓ | ✓ | Default. Native Ollama API. |
| `openai-compatible` | ✓ | ✓ | Generic OpenAI-shape HTTP. Covers vLLM, LM Studio, TGI, LiteLLM. Config: `base_url`, `api_key`, `model`. |
| `openai` | ✓ | ✓ | Same code as openai-compatible with `base_url: https://api.openai.com/v1` and stricter auth. |
| `llama-cpp` | ✓ | ✓ | Talks to `llama-server` on its native endpoints when not in OpenAI-compatible mode. |

Llamafile uses `openai-compatible` since it serves the OpenAI shape on a local port — no separate backend needed.

### Config shape

```yaml
embeddings:
  provider: ollama
  model: mxbai-embed-large:latest

  # Or:
  # provider: openai-compatible
  # base_url: http://localhost:8080/v1
  # model: nomic-embed-text-v1.5
  # api_key: ""              # not required for local

summarization:
  provider: ollama
  model: gemma3:270m
  enabled: false

hyde:
  provider: ollama
  model: gemma3:270m
  enabled: false
```

`summarization.provider` and `hyde.provider` can differ from `embeddings.provider` — embeddings via local Ollama, HyDE via a cloud OpenAI key, for example.

### Migration

Existing configs (`providers.ollama` + `providers.openai` block) keep working with a one-time deprecation shim. New defaults use the per-feature provider shape above.

## C. Preflight + diagnostic UX

### Preflight check on every backend-touching command

When `ctx-sys index`, `search`, `context`, `embed run`, or `serve` starts, run a fast preflight against the configured provider:

1. `healthCheck()` on the embedding provider (2s timeout).
2. If summarization or HyDE is enabled, `healthCheck()` on those providers too.
3. On any failure, print the provider's `detail` + `fix` (see `ProviderHealth` shape above) and exit non-zero.

Example Ollama-not-running output:

```text
✗ Embedding provider (ollama) is not reachable at http://localhost:11434

  Fix: ollama serve
  Or switch provider in .ctx-sys/config.yaml:
       embeddings.provider: openai-compatible
       embeddings.base_url: http://localhost:8080/v1
```

Each backend implements `healthCheck()` to map its specific failures (connection refused → unreachable, 404 on model → model_missing, 401 → auth_failed) to the common shape. Users see consistent messaging regardless of backend.

### Loading-state indicator

The first embedding call after a backend starts can take 30-60s as the model loads into memory. If a call hasn't returned in 3 seconds:

```text
Loading model 'mxbai-embed-large' (first call, this can take ~1 minute)…
```

Spinner / progress until response. Suppressed on subsequent calls.

### `ctx-sys doctor`

Consolidates `debug health` + provider preflight + config validation into one canonical command:

- Runs all provider health checks.
- Validates `.ctx-sys/config.yaml` against the schema (catches typos like `provdier:`).
- Checks for required models on the configured providers.
- Reports DB / index state (folds in F1.4's `status --json` snapshot).
- Per check: PASS / FAIL with the corresponding `fix` line.
- Exits non-zero on any FAIL.
- Supports `--json` (per F1.4).

This is the single command we point users at in any error message: "Run `ctx-sys doctor` to see what's wrong."

### Error message guidelines

- One line: what's wrong (concrete, not abstract).
- One line: how to fix it (copy-pasteable).
- One line: escape hatch (config knob to bypass).
- No stack traces unless `--debug`.
- Centralized in `src/cli/error-handler.ts`.

## What this is not

- An auto-updater. Users own model pulls; we tell them what's missing.
- A model recommender beyond "the default works fine for most repos."
- A bundled inference engine. ctx-sys stays small.
- An LLM benchmark UI. Out of scope; if needed, a separate tool.

- [ ] `ctx-sys setup` runs end-to-end on macOS and Linux, leaving a working installation.

- [ ] Existing configs migrate cleanly via a one-version deprecation shim.

- [ ] First-call loading indicator implemented.
