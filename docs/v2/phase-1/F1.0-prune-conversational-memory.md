# F1.0 Prune Conversational Memory

**Phase**: v2 / Phase 1 — Focus & Sharpen
**Priority**: High
**Dependencies**: none (breaking change — bumps to 2.0.0)

## Goal

Cut the conversational-memory surface area out of ctx-sys (plus the `hooks` git-integration tool) and reposition the project as a pure code-knowledge-graph + hybrid-RAG retrieval system.

## Why

ctx-sys currently ships 12 action-based MCP tools. Half of them — `session`, `message`, `decision`, `checkpoint`, `reflection`, `memory` — implement a conversational-memory layer. That layer:

- **Duplicates other tools in the stack.** lean-ctx ships CCP session memory. Claude Code has CLAUDE.md + native compaction. caveman compresses memory files. mem0/Letta exist for the people who want a real memory product.
- **Splits writes and recall.** When users run ctx-sys alongside lean-ctx (the recommended stack — see F1.3), two memory systems compete. Users end up with half their decisions in each.
- **Dilutes the pitch.** "Local hybrid RAG over your codebase with a knowledge graph" is a sentence. "RAG + sessions + checkpoints + reflections + tiered memory" is a feature list — readers can't tell what the project is *for*.
- **Costs tool-selection budget.** Every MCP tool competes for the LLM's attention when picking what to call. Cutting six tools meaningfully improves the odds the model reaches for `context_query` when it should.
- **Couples unstable schema to stable schema.** Code entities are stable (a function is a function). Conversation semantics evolve fast — what counts as a "reflection" today won't in six months. Coupling them in one SQLite DB makes both harder to iterate on.

The `decision` tool is included in the cut. It looked like a candidate to reframe as a graph node, but the cleaner answer is: **ADRs are markdown documents and ctx-sys already indexes markdown.** Write `docs/decisions/0042-event-store.md`, ctx-sys chunks it, embeds it, and surfaces it next to the code it describes via the existing document indexer + relationship extractor. No special node type, no special tool — and ADR conventions (`Status: Superseded by …`) handle lifecycle without a schema column.

The `hooks` tool (git pre-commit integration + `impact_report`) is also cut. Reasoning: it's a low-traffic feature with a complex install surface (writing into the user's `.git/hooks/`), and the same insight is available on demand via `context_query`. yaao's optional pre-commit integration (which today calls `ctx-sys hooks.impact_report`) becomes a no-op and is removed lockstep with F1.0 — see F1.3 for the yaao-side patch.

## What stays, what goes

### Removed MCP tools

- `session` (create, list, archive, summarize)
- `message` (store, history)
- `decision` (search, create)
- `checkpoint` (save, load, list, delete)
- `reflection` (store, query)
- `memory` (spill, recall, status)
- `hooks` (install, impact_report)

### Removed CLI subcommands

- `ctx-sys session ...`
- `ctx-sys hooks ...`
- (`message`, `decision`, `checkpoint`, `reflection`, `memory` if present)

### Removed source modules

- `src/conversation/` — entire directory
- `src/hooks/` — entire directory
- Conversation-related entity types from `src/entities/`
- Session/message/decision/checkpoint/reflection/memory tables from the schema (see migration below)

### Kept — unchanged

- `context_query`, `entity`, `index`, `graph`, `project`

That leaves **5 MCP tools** down from 12.

## Replacement for `decision` — just markdown

Users who want decisions tracked write them as markdown in their repo:

```text
docs/decisions/0042-event-store.md
```

ctx-sys's document indexer already handles this end-to-end:

- Semantic chunking + embedding → vector search surfaces the ADR for related queries.
- FTS5 → keyword search hits it.
- Relationship extraction can link the doc to entities it mentions by name (e.g., a paragraph naming `EventStore` creates an edge to that entity).

`context_query("why did we pick Postgres for events?")` returns the ADR next to the code. Same outcome the reframed `decision` tool was reaching for, zero new machinery.

Document this in the README as the recommended pattern.

## Schema migration

Schema version bumps current → `v2`. One-way (this is 2.0.0).

**Dropped tables:**

- `sessions`
- `messages`
- `decisions`
- `checkpoints`
- `reflections`
- `memory_tiers` (or whatever the spill/recall table is named)

**Migration steps** (executed by `ctx-sys index --force` or `ctx-sys upgrade`):

1. Detect schema v1 DB at startup.
2. Export sessions/messages/decisions/checkpoints/reflections to `<project>/.ctx-sys/migration-export-v1.jsonl` so users can recover or move them elsewhere (lean-ctx, mem0, a flat markdown log — their choice). Do not delete this file on upgrade.
3. Drop conversation tables.
4. Bump schema version.
5. Print a one-screen migration summary with:

   - Path to the export file.
   - Pointer to lean-ctx / mem0 for users who want session memory back.
   - Note about converting any decisions in the export to markdown ADRs.

## CLI changes

- `ctx-sys session`, `ctx-sys hooks`, and friends print a deprecation notice and a pointer to `migration-export-v1.jsonl` for one minor version, then are removed.
- `ctx-sys debug inspect` no longer lists the removed tables.
- `ctx-sys status --check` no longer reports session/decision counts.

## MCP server changes

- `tool-registry.ts`: remove the seven tool definitions (six conversation + `hooks`).
- Update the server `instructions` string (currently mentions session/memory) to focus on retrieval and the graph.
- Add a single-line note to the README and MCP `instructions` recommending lean-ctx for session memory and caveman for output/memory-file compression.

## Migration & release notes

Release as `ctx-sys@2.0.0`. CHANGELOG entry should lead with:

> **Breaking:** ctx-sys 2.0 removes the conversational-memory layer (`session`, `message`, `decision`, `checkpoint`, `reflection`, `memory` tools) and the `hooks` git-integration tool to focus on its strongest capability: hybrid RAG over a code knowledge graph. Existing session/decision data is exported to `.ctx-sys/migration-export-v1.jsonl` on first run. Users who want session memory should pair ctx-sys with lean-ctx; users who tracked architectural decisions in ctx-sys should convert them to markdown ADRs in their repo — ctx-sys's document indexer surfaces them automatically.
