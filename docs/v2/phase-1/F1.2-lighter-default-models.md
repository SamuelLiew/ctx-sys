# F1.2 Lighter Default Models

**Phase**: v2 / Phase 1 — Focus & Sharpen
**Priority**: Medium
**Dependencies**: none

## Goal

Drop the default model for both HyDE query expansion and summarization to **`gemma3:270m`**. Keep both features fully optional. Stop asking users to pull a 12B model just to try ctx-sys.

## Why

Current README defaults:

| Feature        | Current default     | Approx. VRAM/RAM |
| -------------- | ------------------- | ---------------- |
| Embeddings     | `mxbai-embed-large` | ~1.5 GB          |
| Summarization  | `qwen3:0.6b`        | ~1 GB            |
| HyDE expansion | `gemma3:12b`        | ~8–10 GB         |

A user trying ctx-sys for the first time, on a 16 GB laptop, hits a wall the moment they enable HyDE. They either silently keep HyDE off (losing a real feature) or give up. Even `qwen3:0.6b` for summarization is heavier than it needs to be when summaries are short, structured, and rerun on every code change.

`gemma3:270m` is small enough that it ships in seconds, runs fully on CPU, and is more than sufficient for the two tasks ctx-sys uses it for:

- **HyDE.** Generate a hypothetical answer paragraph to embed for retrieval. Doesn't need a strong reasoner — the embedding is what matters; the text just has to use roughly the right vocabulary.
- **Summarization.** One-paragraph summaries of entities (functions, classes, docs). These are short, formulaic, and consumed by retrieval — not by a human reading them top-to-bottom.

Both jobs are *retrieval-shaped*, not *reasoning-shaped*. A 270M model is the right tool.

## What changes

### Config defaults

`.ctx-sys/config.yaml` template generated by `ctx-sys init`:

```yaml
summarization:
  provider: ollama
  model: gemma3:270m     # was qwen3:0.6b

hyde:
  provider: ollama
  model: gemma3:270m     # was gemma3:12b
  enabled: false         # explicit — HyDE stays opt-in
```

A single small model now covers both features, so users only pull one extra model beyond the embedder.

### Documentation

README "Requirements" table:

```
- mxbai-embed-large:latest — embedding model (1024 dims, ~1.5 GB)
- gemma3:270m              — summarization + HyDE (optional, ~300 MB)
```

Remove the `qwen3:0.6b` and `gemma3:12b` lines. Add a short paragraph:

> ctx-sys defaults to the smallest viable model for summarization and HyDE because both jobs are retrieval-shaped, not reasoning-shaped — the embedder does the heavy lifting. If you want higher-quality summaries or HyDE expansions, override `summarization.model` / `hyde.model` in `.ctx-sys/config.yaml` to any Ollama-compatible model. Larger models will not necessarily improve retrieval; measure before committing.

### HyDE remains opt-in

`hyde.enabled: false` by default. Enabled via:
- `.ctx-sys/config.yaml` (`hyde.enabled: true`)
- per-call flag: `ctx-sys search "query" --hyde`
- per-call MCP tool argument: `context_query({ hyde: true, ... })`

No change to the opt-in behavior — just the default model.

### Summarization remains opt-in (verify)

If summarization currently runs as part of `ctx-sys index` by default, gate it behind `summarization.enabled` (default `false`) and a `--summarize` flag on `index`. Generating summaries for every entity on first index is slow and many users won't notice the benefit. Confirm current behavior and adjust if needed.

## Migration

- Existing configs keep their current models — no silent override.
- On `ctx-sys index`, if the configured `hyde.model` or `summarization.model` is not present in Ollama, print a one-line tip: *"You can switch to `gemma3:270m` for a faster, lighter setup — see `.ctx-sys/config.yaml`."*

## Acceptance criteria

- [ ] `DEFAULT_PROJECT_CONFIG_FILE` uses `gemma3:270m` for both `summarization.model` and `hyde.model`.
- [ ] `hyde.enabled` defaults to `false`.
- [ ] `summarization.enabled` is explicit (default `false` unless already shipped enabled).
- [ ] README "Requirements" reflects the single-model setup.
- [ ] Existing configs are not rewritten on upgrade.
- [ ] A regression test confirms ctx-sys works end-to-end with `gemma3:270m` only (no `gemma3:12b`, no `qwen3:0.6b`).
