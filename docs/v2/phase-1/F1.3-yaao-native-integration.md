# F1.3 yaao Native Integration

**Phase**: v2 / Phase 1 — Focus & Sharpen
**Priority**: Medium
**Dependencies**: F1.0 (directive cleanup), F1.1 (`.yaao/` in seeded `.ctxignore`), F1.4 (MCP polish — `status --json` schema, tool descriptions)

## Goal

Close the yaao-specific gaps so ctx-sys is a first-class, optional retrieval peer for yaao. The integration is already mostly built on the yaao side — this doc keeps ctx-sys's side honest. Generic MCP improvements live in F1.4.

## Current state — what yaao already does

yaao ([/Users/davidfranz/Documents/project-experiments/yaao](../../../../../yaao)) is a multi-agent orchestrator. It already treats ctx-sys as an optional MCP peer:

- **Detection** — [yaao/src/ctx-sys/detect.ts](../../../../../yaao/src/ctx-sys/detect.ts) probes for `.ctx-sys/` and the `ctx-sys` binary on PATH.
- **Auto-spawn** — [yaao/src/ctx-sys/spawn.ts](../../../../../yaao/src/ctx-sys/spawn.ts) runs `ctx-sys serve --socket <path>` and waits for readiness when `auto-spawn: true`.
- **MCP registration** — [yaao/src/ctx-sys/mcp-config.ts](../../../../../yaao/src/ctx-sys/mcp-config.ts) registers the ctx-sys socket as an MCP server alongside yaao's own.
- **Directive injection** — [yaao/src/ctx-sys/directive.ts](../../../../../yaao/src/ctx-sys/directive.ts) adds a system-prompt advisory urging `context_query` before code changes.
- **Optional git hook (being removed)** — [yaao/src/ctx-sys/hooks.ts](../../../../../yaao/src/ctx-sys/hooks.ts) calls `ctx-sys hooks.impact_report` on pre-commit. F1.0 cuts the underlying ctx-sys feature; see Gap 3 below for the yaao-side cleanup.

By default, all tasks in a yaao run share one ctx-sys process spawned at the project root. Tasks run in per-task worktrees under `.yaao/worktrees/<run-id>/<task-id>/` but talk to that single ctx-sys process over MCP; ctx-sys returns repo-relative paths, which resolve correctly inside any worktree. So worktrees are not a runtime problem.

The only worktree concern is **indexing-side**: `ctx-sys index` running from the main checkout shouldn't walk into `.yaao/worktrees/`. F1.1's seeded `.ctxignore` handles that.

## Gaps

### 1. Formalize `ctx-sys serve --socket <path>`

yaao's spawn code calls `ctx-sys serve --socket <path>` and waits for a `ready` signal. Verify this works today and lock it in as a stable contract:

- `--socket <path>`: open a Unix domain socket (named pipe on Windows) for MCP stdio over that socket. Useful for parents that don't want to share the process's stdio.
- Print `ctx-sys: ready` on stderr when the server is accepting connections, so yaao can stop polling.
- On `SIGTERM`, drain in-flight requests for up to 5s then exit cleanly.

If any of this is missing today, add it. If it already works, add a regression test that locks the contract.

### 2. Directive cleanup (lockstep with F1.0)

[yaao/src/ctx-sys/directive.ts](../../../../../yaao/src/ctx-sys/directive.ts) currently advises agents to use ctx-sys for "context, sessions, and memory". After F1.0 the directive must be retuned to focus on retrieval only:

- Remove session/memory/decision language.
- Single sentence: *"This project has ctx-sys available. Call `context_query` before reading or writing code; the codebase is indexed and search will be faster and more accurate than blind file reads."*
- Tied to F1.0's release — ship in the same window.

### 3. Remove yaao's pre-commit hook integration (lockstep with F1.0)

F1.0 cuts ctx-sys's `hooks` MCP tool and `ctx-sys hooks ...` CLI subcommand. yaao's [hooks.ts](../../../../../yaao/src/ctx-sys/hooks.ts), which today calls `ctx-sys hooks.impact_report` on pre-commit, becomes dead code:

- Delete `yaao/src/ctx-sys/hooks.ts`.
- Remove the optional pre-commit wiring from yaao's `ctx-sys` integration.
- Remove the `hooks` knob from yaao's ctx-sys config schema (if present).
- yaao's own non-ctx-sys hooks (merge journals, validation runners) are unaffected.

### 4. README cross-links

- ctx-sys README: short section *"Using ctx-sys with yaao"* with the three-line setup (`yaao init` + `ctx-sys init` + `ctx-sys index`, then flip `ctx-sys.enabled: true` in `.yaao/yaao.config.json`).
- yaao README: reciprocal mention pointing back.

## Open questions

- **Concurrent ctx-sys queries.** Multiple yaao tasks query ctx-sys in parallel. SQLite is single-writer but multi-reader, and ctx-sys's read path is read-only — should be fine. Add a stress test (10 parallel `context_query` calls) to confirm no lock contention.
- **Monorepos.** If yaao runs tasks across sibling packages, recommend one ctx-sys index per `.yaao/` root. Document.

## Explicitly out of scope

- Worktree-parent resolution. The `.ctxignore` default + shared-process-at-root design covers it.
- Journal ingestion. ctx-sys is "current state of code"; yaao owns run history. Surfacing "this entity was touched by agent X" can come back later as a generic annotation API if a real user asks.
- Bundled `ctx-query` skill. ctx-sys's MCP tool with a great description is sufficient; a skill wrapper is redundant plumbing.
- `status --json` schema and tool description sharpening — both in F1.4.
